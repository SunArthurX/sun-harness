Design questions

Why rank fusion instead of adding the scores?

BM25 scores are unbounded and depend on the corpus; cosine similarity lives in [−1, 1] and depends on the model. Adding them would need per-corpus tuning. Reciprocal rank fusion uses only positions, so the two lists combine fairly, and a note that is good in both rises to the top. A test pins this with a note matching both lexically and semantically.

How does it avoid re-embedding the whole knowledge base on every change?

The cache is content-addressed: the key is sha1(model + chunk text). Editing one file re-embeds only that file's changed chunks; chunks of deleted files are pruned; switching models changes every key, so nothing stale is reused. Vectors are stored as base64 Float32, about a quarter of the size of JSON numbers.

What happens when the embedding provider is down or out of balance?

Search still answers. The hybrid provider catches the error, returns BM25 results, and records lastError, which the Knowledge screen shows. During development GLM's embedding endpoint answered 余额不足 (insufficient balance), which made a convenient live test of exactly this path.

Why is it off by default?

Turning it on sends your notes to a third-party API. Under human in control, that is a choice you make in Settings, not a default.

Design the seam before the feature. Because KnowledgeProvider existed from day one, hybrid search is one new class that wraps the old one; no caller changed.
