Remote connections and recovery

The gateway already supported pinned TLS and per-device tokens. This milestone added live revocation, request receipts, browser authentication, and a desktop connection panel.

How does the gateway recognize a retry?

The client sends the same request ID after a lost response. The gateway scopes it to the authenticated device and checks the payload digest before reusing the first outcome. The acceptance window and gateway instance binding prevent a request from being executed again after its receipt is gone.

stateDiagram-v2
  [*] --> Stale
  Stale --> Refreshing: Event stream opens
  Refreshing --> Ready: Identity and state refreshed
  Ready --> Stale: Stream interrupted
  Refreshing --> Stale: Refresh interrupted
  Ready --> Revoked: Device access revoked
  Revoked --> [*]

What changes when a device is revoked?

The gateway closes that device's live streams and releases its approver registrations. If no authorized approver remains, pending approvals resolve as denied. A reply requires the exact prompt ID from the current host. Desktop calls carry the bound installation identity, and switching hosts invalidates requests from the old renderer document.

What happens to a draft during reconnect?

The client keeps the displayed state and disables host writes. When events resume, it refreshes settings, sessions, and approvals. The draft retains its original revision, so a concurrent settings change still requires review.
