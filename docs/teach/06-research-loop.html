06 · The research loop

The MVP is only the start. The plan is a loop: watch the field, pick the highest-value gap, write a spec, build, test, document, repeat. Here is the first full turn of that loop.

1 · The finding

The 2026-11-07 briefing covered Claude Code 2.1.317–2.1.319. Its headline was fail-closed autonomy: when the auto-mode classifier cannot be reached, risky calls are now asked or denied instead of approved by a local fallback. It also highlighted two related primitives:

  • permissions.denyInsteadOfPrompting: a call that would block on a prompt is denied, and the turn continues.
  • Hook onFailure: "block": a failing policy callback vetoes the action instead of letting it through.

2 · Does it apply here? (first principles)

Which of the six parts does this touch? Policy. Did sun-harness have the problem? Yes, in two places:

What did sun-harness do with an approval in a headless run?

It waited forever. sun run with piped input, a launchd job, or a desktop app whose window was closed would raise an approval that no one could answer. The intel finding exposed a real latent bug.

What did a crashing preToolUse hook do?

Any exit code other than 2 was ignored, so a broken policy script silently disabled the policy.

3 · The design

flowchart TB Q[Tool needs approval] --> A{Approver registered?
desktop window / interactive TTY} A -->|no| D1[deny + reason: headless run] A -->|yes| B{denyInsteadOfPrompting?} B -->|yes| D2[deny + reason] B -->|no| ASK[show approval card / prompt] D1 & D2 --> R[reason logged on approval/decision
and returned to the model as the tool result] R --> CONT[agent continues without the tool]
  • UIs announce themselves with host.registerApprover(). The desktop registers when its window opens; the CLI registers only when stdin is a TTY.
  • The deny carries a reason, so the model can adapt ("I could not run the tests; here is what I need") instead of retrying blindly.
  • Hooks gain onFailure: "block". The default stays ignore, so existing hook files keep working.

4 · Tests that pin it

✓ denies instead of hanging when no approver is attached (headless), with a reason for the model
✓ denyInsteadOfPrompting denies even with an approver attached
✓ onFailure "block" makes a crashing policy hook fail closed; default ignores it

Existing approval tests now register an approver explicitly. That made the new rule visible in the test code itself: without someone to ask, the answer is no.
