01 · First principles

Before writing code: what is an agent harness, really? If we can name the irreducible parts, the MVP is just those parts done well, and every other feature becomes an extension.

A harness has six parts

Strip away the UI and branding of Claude Code, Codex, DeepSeek Harness, Cursor, Manus or Hermes, and the same six things remain:

PartQuestionIf it is missing…
ModelWho thinks?nothing happens
ContextWhat does it know about this task, this repo, this person?generic answers, drift from project conventions

LoopHow does it keep going until done?one-shot answers, no verification
LogWhat happened, durably?no resume, no audit, no learning

The MVP, derived

The minimum useful harness is those six parts, each in its simplest durable form:

  • Model: two wire formats cover almost every provider: OpenAI Chat Completions and the Anthropic Messages API.
  • Context: the project's own files (AGENTS.md, specs) assembled fresh on every request.
  • Tools: read, write, edit, search, shell, web. That is enough for coding and for most general tasks.
  • Loop: "if a request is owed, ask the model; if it called tools, run them; repeat."
  • Log: append-only JSONL, one file per session. No database.
  • Policy: three approval modes keyed on a tool's risk (read, write, exec, network).

Everything else, from the desktop UI to MCP, plugins, knowledge, intel and evolution, plugs into one of these parts.

Rules that prevent drift

An AI-built project drifts when the reasons for decisions live only in chat history. The fix is to put the reasons in files that every agent reads on every request, and to order them by authority:

flowchart TB S[specs/ — product behavior
000-vision is the north star] --> P[docs/plan.md — milestones] P --> A[AGENTS.md — how to work] A --> C[Code] C -. "behavior change" .-> S

The repository's AGENTS.md codifies four things: English-only artifacts, spec-first changes (a behavior change updates its spec in the same change), the first principles above as design constraints, and a definition of done per milestone: tests and build pass, the manual is updated, and a teaching page like this one is added.

Why AGENTS.md and not a custom format?

It is the de-facto cross-tool convention (Codex, Cursor, DeepSeek Harness, and others read it). CLAUDE.md is a symlink to it, so Claude Code reads the same rules. One file, every tool.

Why write everything in English?

Models are strongest in English, most upstream documentation is English, and a single language keeps rules, specs and code comments consistent. Chat with the owner can be in any language; the artifacts are English. This rule lives in AGENTS.md §1.

Electron or Tauri for the desktop?

Electron. The core is TypeScript on Node (MCP SDK, child processes, file system). Electron lets the main process host that core directly; Tauri would need a Node sidecar or a Rust rewrite. The cost is app size, which does not matter for a personal tool.
