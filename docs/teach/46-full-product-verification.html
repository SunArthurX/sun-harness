Full product verification

The same feature can fail at different boundaries. The runtime test can confirm an approval is pending while a renderer test reveals that a pinned plan intercepts the click. The command-line process can hang after the runtime returned if a connection timer still owns the event loop.

Why run the program as a process?

A scripted HTTP provider returns a recoverable quota error or a terminal failure. The built CLI must propagate different exit codes. The gateway fixture closes stdin before attachment completes so buffered lines must survive connection setup. A real MCP server verifies both discovered tools and that the process exits after it closes the transport.

How do we prove callback routing stays isolated?

Hold a model response while a second signed or authenticated request arrives. Use different loopback reply addresses and record their actual payloads. A denied caller receives its own identity message. The delayed authorized reply goes only to the original destination. A concurrent authorized generic webhook receives an explicit same-chat conflict while the synchronous collector owns that chat.

Why did a JSON null break an image?

The desktop calls readAttachment(path) with one argument. The gateway sends arguments as a JSON array, where an omitted trailing argument becomes null. The host treated any non-undefined value as Appshot metadata, so an ordinary PNG failed the Appshot digest check. The fix normalizes null only at the gateway boundary. The host's validation of real Appshot metadata is unchanged.

When is a failure the fixture's fault?

The Electron fixture isolates HOME. Headless Chrome then had no login keychain and waited before its first network request. A probe outside the fixture separated the variables. With the real HOME, navigation took milliseconds. With an empty HOME, it timed out. With --use-mock-keychain, it worked again. The flag belongs in the test launcher only, because real profiles need encrypted cookies.

Why must quit wait?

Electron does not terminate child processes on macOS. The quit handler started an asynchronous disposal without waiting, so the app could exit before the browser was told to stop. Even when the stop signal was sent, disposal released the profile while Chromium was still writing to it. Two cleanup failures (ENOTEMPTY) and an orphaned process under launchd revealed this. A test now checks the process list for the profile after quit and after disposal.

The first version of that fix caused its own regression. The final package was still running after the Computer Use fixture had sent it one SIGTERM. Logging inside before-quit showed that a quit requested in the same task as the signal's quit closed the windows but produced window-all-closed, which does not quit on macOS. Deferring the second quit by one task fixed it. A process-level check now sends exactly one signal to a fresh app. A related leak came from launch timeouts: a Chrome that missed its startup deadline was abandoned, so startup failures now stop the process they spawned.

One failing command, one lost session

Driving every CLI slash command through one piped session showed that a single failing command (/reflect with a non-JSON reply) ended the whole process. Only a test that issues later commands after the failure can catch this. The loop now reports the failure and continues.
