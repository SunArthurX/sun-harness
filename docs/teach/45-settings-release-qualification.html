Settings release qualification

The release combines cross-surface behavior, signed native evidence, and a live handoff check. A test can prove only the route it exercised. Desktop settings, gateway transport, local browser backends, and the signed macOS helpers have separate acceptance records.

How does the handoff test expose drift?

The test freezes a public prompt, three task fixtures, a write scope, and the fixed judge. The untouched fixtures fail and the reference patches pass before the model runs. Each attempt uses a fresh workspace. The report saves the exact prompt and fixture hashes, the diff, the run status, and the acceptance output.

flowchart TD
  A[Freeze the public prompt and fixture suite] --> B[Validate untouched and reference outcomes]
  B --> C[Run three fresh repetitions per fixture]
  C --> D[Record each attempt and fixed judge output]
  D --> E{Nine first-attempt passes for these hashes?}
  E -->|Yes| F[Record live handoff acceptance]
  E -->|No| G[Preserve the failed report and investigate]

Why does a paused run fail even with a passing diff?

A useful handoff includes a bounded finish and a final report. In the first T15 run, one model attempt produced a passing settings diff but reached its step limit before finishing. A second run exposed a test stub that returned an error object instead of throwing. The public prompt now covers both the test boundary and when to finish. A prompt extraction regression test checks that the runner sends the entire quote. The final run passed all nine attempts with the same judge, fixture scope, model, and step limit.
