Review and worktree safety

Review began as a one-shot model request over checkpoint diffs. This milestone records what the model receives and validates what it cites. Worktree operations now check ownership, activity, and checkout state before modifying Git state.

flowchart TD
  A[Candidate changes] --> B[Digest all candidate files]
  B --> C[Select whole diffs within the budget]
  C --> D[Flush provider request to session log]
  D --> E[Validate paths, changed lines and evidence]
  E --> F[Persist findings and omissions]
  F --> G[Recompute digest before completion]
  G -->|Current and complete| H[Evaluate completion gate]
  G -->|Changed or incomplete| I[Pause when the gate is enabled]

How can Git inspection include untracked files?

A copy of the worktree index receives intent-to-add entries. Diff and review use that copy to compare the candidate with the recorded commit. The actual index remains available for the user's own staging decisions.

How do merge and discard preserve work?

Merge retains the candidate as a branch commit before updating the destination. Cleanup requires a clean worktree, including untracked and ignored files, and uses Git's ordinary removal command. A branch whose commits are still unmerged remains reachable.
