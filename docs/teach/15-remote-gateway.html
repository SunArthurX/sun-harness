15 · The remote gateway

Your laptop, a second Mac, or a bot server should be able to use the harness at home. That means leaving localhost, which requires encryption, a trust decision, and credentials you can revoke per device.

Design questions

Why not Let's Encrypt?

A personal gateway on 192.168.0.216 has no public domain to validate. Pinning the self-signed certificate is stronger here: a CA can issue a valid certificate for your name to someone else, but nobody else can produce your key's fingerprint.

What stops someone from simply binding to 0.0.0.0 over HTTP?

The gateway does: startGateway throws if the address is not loopback and TLS is off. An explicit --insecure exists for tunnels that already encrypt, and is documented as unsafe.

A wrong fingerprint was accepted in testing. Why?

Node's shared HTTPS agent pools TLS connections. A client with the correct pin opened a connection; a second client with a wrong pin then got that already-verified socket from the pool, and checkServerIdentity never ran. The test caught it. The fix is agent: false (no pooled sockets for pinned clients) plus a second fingerprint check on every response's socket. Verification code is only as good as the connection it actually runs on.

Why one token per device instead of the owner token everywhere?

Revocation and audit. A lost laptop costs one revoke, not a reset of every client. Tokens are shown once and stored only as SHA-256 hashes, compared in constant time; token list shows each device's last use.

How was it verified live?

A TLS gateway with its own home listened on 0.0.0.0:4490. A client with a separate home ran remote add against the LAN address: a wrong --fingerprint was refused and not saved, the correct one connected, and a session ran on the server (visible in its session list, with the token's last use updated). After token revoke, the client got "Gateway rejected the token".

Make the secure path the only easy path: no TLS, no network binding; no matching fingerprint, no connection; one token per device, revocable in one command.
