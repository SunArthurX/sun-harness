14 · The approval guard

An approval is only meaningful if the human saw what they approved. Claude Code 2.1.318 fixed prompts that could be answered by keystrokes typed before the prompt appeared. sun-harness had the same race in three places.

Three races, three fixes

RaceWhereFix
You are typing a chat message; the prompt appears; your Enter answers itCLI chatclear the half-typed line when the prompt appears
Keys typed during a run sit in the terminal buffer and answer the prompt the instant it is createdCLI rundiscard answers that arrive within 400 ms of the prompt; ask again
A card pops up under your cursor and the next click lands on Allowdesktop, webbuttons arm after 700 ms ("read first…"), focus leaves the composer
An old window answers a prompt that was re-issued after a restartany clienta fresh promptId per showing; answers must quote it

Design questions

Why a time window rather than flushing stdin?

Node gives no portable way to drop bytes already buffered by the TTY before a readline interface reads them. A minimum reaction time works whatever the buffering: nobody reads a command and answers in under 400 ms, so any faster answer was typed before the prompt.

What does the prompt id add, if call ids are already unique?

The same call can be asked twice: the app restarts, the run resumes, the approval is re-requested with the same callId. A UI still showing the first prompt must not be able to answer the second. Each showing gets a new promptId; approve() returns false (an error over HTTP) for stale ids, unknown calls, and second answers.

Was it tested in a real terminal?

Yes, in tmux: y⏎ was sent half a second after starting sun run, before the approval appeared. The prompt showed the ignore message and asked again; only the later y ran the command. The desktop end-to-end test clicks Allow programmatically the moment the card appears and asserts the approval is still pending.

Consent needs proof of attention. Bind each answer to the exact prompt, and refuse answers that arrived faster than a person could have read it.
