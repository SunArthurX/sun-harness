27 · Code the way Cursor does

Each competitor has a short list of things it does better. Most of those lists are already in sun-harness: sandbox, plan mode, checkpoints, LSP, memory, MCP. What was still missing, and what makes Cursor's agent feel oriented inside a repository, is three moves: find the code, attach the rule for that file, and review the diff without editing it.

What each product was best at

flowchart LR C[Cursor] --> S[codebase search] C --> R[glob rules and @rule] C --> V[review the diff] CC[Claude Code] --> S CX[Codex] --> V S --> H[HarnessHost] R --> H V --> H

Why not ship a feature for every cell of the comparison?

Manus's cloud computer, Hermes's self-written skills, and OpenCode's model menu are already covered or are a different product. Copying the label without a gap would only add surface. The spec table records the three strengths and marks the ones this release actually adds.

Search stays on disk

Cursor's index is a background embedding job. A personal harness should still answer "where is chargeInvoice?" with the laptop off the network. codebase_search chunks source files, scores them with the same BM25 tokenizer as the knowledge base, and if the query is a single identifier it also returns the matching definition from the repository map's patterns. The cache key is the file mtimes, so an edit shows up on the next search.

How does a secret stay out of that index?

.cursorignore and .sunignore are read with gitignore rules: *, **, ?, a trailing slash for a directory, and ! to un-ignore. read_file, grep, glob, and @file check the same list and return a refusal instead of the bytes. The model sees the refusal, not the token.

Rules that wake up when the file does

A rule with globs: src/**/*.ts used to be treated like any other description: a one-line hint, globs ignored. Now the body is appended only after the conversation has touched a matching path. The first request stays cacheable; the next request, after read_file, carries the rule. @rule api pulls a manual rule immediately.

sequenceDiagram participant U as User participant A as Agent participant P as Prompt U->>A: edit the parser A->>P: request 1, no file yet A->>A: read_file src/parser.ts A->>P: request 2 includes rules whose globs match src/parser.ts

Why *.ts does not match src/a.ts?

That is Cursor's rule table, not gitignore. A pattern with no slash is the project root. **/*.ts is every directory. Ignore files keep the gitignore meaning, because that is what .cursorignore documents.

Review is a reader

/review builds the same diff as the Changes panel and asks the session model to name bugs, missing tests, and security issues. The answer is a review/report event. It is not fed back into deriveMessages, so a review does not silently become the agent's next instruction. An empty session does not spend a model call.

Lessons

  • A competitor matrix is a filter. Build the cell that is still empty and that changes how code gets written.
  • File-scoped rules belong at the end of the prompt, after the model has actually opened the file, or the prefix cache breaks on every turn.
  • Search, ignore, and review share one path check. A secret that search can quote is not ignored.
