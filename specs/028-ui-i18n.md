# 028 — Desktop and web UI languages

Status: implemented (0.8.0). Code: `apps/desktop/src/renderer/src/i18n.ts`, `locale-zh-CN.ts`, `apps/desktop/scripts/i18n.mjs`, `apps/desktop/test/i18n.test.ts`. Config: `ui.language`. ADR: `docs/adr/0009-ui-i18n.md`.

## Goal

Every desktop and gateway web page is available in **English** and **Simplified Chinese**. A later feature that adds UI copy is not done until both languages ship.

Docs, specs, comments, CLI output, and model-facing prompts stay English (`AGENTS.md`). The UI is the exception: source strings are English; Simplified Chinese is a translation of those strings.

## Decision

Gettext-style keys: the English sentence *is* the key. `t('Open')` renders `Open` in English and the `locale-zh-CN.ts` value in Simplified Chinese. A missing translation falls back to English instead of showing a lookup id.

`tk('Sessions')` marks a module-level English string so the scanner sees it; render with `t(value)` later.

## Language setting

`config.ui.language`: `system` (default) | `en` | `zh-CN`.

- `system` follows the OS / browser: any `zh*` locale → Simplified Chinese, everything else → English.
- Stored in `~/.sun/config.json`. The Settings page offers System / English / 简体中文. The left rail toggles English ↔ 简体中文 (writes `en` or `zh-CN`).
- Applied before the first React render (`main.tsx`). Changing it re-renders immediately (`onLangChange`, `document.documentElement.lang`).

The CLI is not localized.

## What must be translated

User-visible chrome: navigation, page titles, buttons, labels, placeholders, titles/tooltips, empty states, confirm/alert/prompt, notifications, status words shown in the UI (session status, tool risk, file change, job state, skill scope, …).

Not translated: the user's own text, model replies, file contents, session titles, tool arguments/output, product identifiers (`sun-harness`, model ids, URLs).

Context-report suggestions come from core as English templates (`suggestionKeys`); the desktop translates those templates with the same `t()` keys.

## Every new feature

In the same change as the UI:

1. Wrap new copy in `t()` / `tk()` (English source).
2. Add the Simplified Chinese entry to `locale-zh-CN.ts` (same `{name}` placeholders).
3. `pnpm test` — `apps/desktop/test/i18n.test.ts` fails if a JSX string is not wrapped, a key has no Chinese, placeholders drifted, or the Chinese is still the English.

`apps/desktop/scripts/i18n.mjs` is the scanner (`node apps/desktop/scripts/i18n.mjs` lists leftovers; `--fix` wraps plain JSX text).

## Screens

Welcome, Sessions, Chat, Composer, Context report, Changes, Browser, Knowledge, Extensions, Evolution, Intel, Settings, Automations, command palette — all go through `t()`.

Decision (T04): Translation coverage scans all renderer subdirectories. The settings search index uses English and Simplified Chinese strings together, independent of the selected display language.
